# engineering/qa/ — 验证记录与证据生成工具

本目录回答「这次**做得怎么样**」（根 `AGENTS.md` §7）。三类内容：

| 形态 | 用途 | 入库要求 |
|---|---|---|
| `YYYY-MM-DD-<主题>.md` | QA 记录：范围、验收口径、实际执行命令与用例数、未运行项、结论 | **证据是结论的必要附件** —— 接口用例附 curl / 终端输出快照，置于 `evidence/` 引用文件名 |
| `evidence/` | 原始输出快照（门禁输出、冒烟日志、反例失败输出） | 只放**原始未加工**的输出；任何"精选/美化"都会让证据失去复核价值 |
| `_*.py` | **一次性探针 / 证据生成脚本**（见下） | 见「为什么保留」 |

## 关于 `_*.py`

这些不是残留的临时文件，而是**产出上述证据的工具**。例如：

| 脚本 | 用途 |
|---|---|
| `_probe_flyway_004.py` / `_probe_flyway_db.py` | Flyway 迁移实测的探针（验证 `DELIMITER` 阻断、`baseline-version` 行为） |
| `_probe_preflight.py` | 前置闸门 `preflight-baseline-check.mjs` 三条路径的真机验证 |
| `_rewrite_004.py` | 用 `git show HEAD:` + 程序化替换改写 `migration-004`，保证未触及部分**逐字节不变** |
| `_chat_branches.py` | 统计 `ChatMessage.vue` 模板分支，用于死组件事故的复盘 |
| `_apply_adb.py` / `_count_mut.py` | `ADB.js` 缺陷验证、变异脚本计数 |

**为什么保留**（2026-10-06 订正）：一次只读盘点曾把它们列为「仓库卫生问题」并建议删除。
核查后发现 **7 个里有 5 个被 QA 文档按名引用** —— 它们是证据的**可复现性载体**，
删掉会让那些 QA 结论变成「无法复核的历史陈述」。

**判定规则**：一个探针脚本可以删，当且仅当**没有任何 QA / Retro 文档引用它**。
删除前先 grep 确认，别凭文件名判断。

## 命名约定

- `_` 前缀 = 非交付物（工具/探针）；QA 记录本身不带前缀。
- 落盘前确认目标文件**不在黑名单**里（`pre-commit-guard` 会拦 `*.log` / `*-out.txt` 等，
  但**不拦** `.py`，故脚本入库是允许的）。
- 证据文件名带日期与主题，避免同名覆盖。
