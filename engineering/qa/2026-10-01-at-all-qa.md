## 3. 实际执行的验证命令与结果

### 3.1 构建

```
cd easychat-front && npm run build
```

结果：**通过，0 error**（main / preload / renderer 三段均 built）。

### 3.2 ESLint（确认无新增 error）

```
npx eslint src/renderer/src/views/chat/MessageSend.vue src/renderer/src/views/chat/ChatMessage.vue
```

结果：`17 errors, 1703 warnings`。

- 首次运行报 **19 errors**，其中 2 条为本次改动引入的真实缺陷：
  `307:20 / 307:38 error 'inputRef' is not defined` —— 模板加了 `ref="inputRef"`
  但脚本未声明该 ref，运行到 `insertAtText()` 会抛 `ReferenceError`（整个聊天页白屏）。
  **已修复**：在 @ 状态块补 `const inputRef = ref()`。
- 剩余 17 条全部为改动前既有代码，未触碰：ChatMessage.vue 的 `ref/reactive/nextTick/proxy`
  未使用导入、两个 prop `default: {}` 写法；MessageSend.vue 的 emoji `v-for` 缺 `:key`、
  `sendMessageDo` 默认参数解构未定义变量、`fileId` 未使用。

### 3.3 构建产物断言

```
Get-ChildItem out/renderer/assets/Chat-*.js  → at-all-tag=True  at-all-message=True  at-icon=True
Get-ChildItem out/renderer/assets/Chat-*.css → at-panel=True    at-item-all=True
Get-ChildItem out/renderer/assets/index-*.css→ --ec-at-all=True
```

结果：模板、逻辑、样式、主题变量四类改动均已实际产出到构建产物（排除「编译通过但未生效」）。
