# Retro — 收藏功能（前端补齐）

- 关联 Change: openspec/changes/2026-09-30-favorite
- 关联 QA: engineering/qa/2026-10-02-favorite.md

## 做得好

1. **用「孤路由」当探针，接线状态一目了然**。`check-api-contract.mjs` 报的 3 个 favorite 孤路由就是「后端写好了但前端没接」的精确信号——修完前端后这 3 个自动消失，比人肉 grep 可靠。
2. **入口放在设置页而非新窗口**，与「文件管理 / 数据备份 / 关于」同构，用户心智一致；路由 `/setting/favorite` 复用既有 `Setting.vue` 的左右布局，零新增框架代码。
3. **收藏内容取值按消息类型分流**（媒体存文件名+路径、文本/位置存正文），与后端 `content` / `file_path` 两字段的语义对齐，避免列表里出现空白。

## 问题

1. **「后端完成」被当成「功能完成」**。本变更 2026-09-30 归档时前端为零，但 tasks 里后端阶段全勾、QA 结论正常，没有任何信号提示「用户还不能用」。
2. **spec 是 1 句占位**（「用户收藏消息。」），却描述了完整前端行为（右键菜单、收藏列表页），与实现脱节。
3. **接口活体未跑**。本次只做了静态与构建验证，`/favorite/add` 未在运行中的后端上实测。

## 原因

- 归档判据是「tasks 全勾 + QA 存在」，而不是「用户可感知」。
- spec 先于实现写，且写得像需求而非事实，导致「spec 存在」被误读为「行为已成立」。

## 改进方案

| 优先级 | 方案 | 落点 |
|--------|------|------|
| 高 | 归档前跑一次 `check-api-contract.mjs`，孤路由必须清零或有明确归属说明 | 归档自查清单 |
| 中 | spec 占位式 Requirement（一句话无 Scenario）在 hygiene 中告警 | `scripts/check-openspec-hygiene.mjs` |
| 中 | 前端变更的 QA 增加「接口活体」一行：至少对新增端点打一次（哪怕只验 200/参数错误） | `templates/_qa_template.md` |

## 遗留 / 后续

- GUI 右键交互与 `/favorite/add` 活体待本机手动验证。
- `favorite/list` 未分页（后端返回全量），收藏量大时需另开变更加分页。
