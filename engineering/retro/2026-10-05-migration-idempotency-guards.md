# Retro — 迁移脚本幂等性守卫（遗留 #10）

- 日期: 2026-10-05
- 效率等级: L4
- 关联 QA: `engineering/qa/2026-10-05-migration-idempotency-guards.md`

## 做得好的

1. **立项前先把台账本身审了一遍，而不是照着做**。台账写「6/12 份非幂等，含 011」，实测 011 的 `ADD COLUMN` **全部已有守卫**。若直接照做，会对一份已经正确的脚本动刀，还会带着「12 份里错了 1 份」的错账进 QA。
2. **checksum 风险查到了机制层**。没有停在「改迁移脚本有风险」，而是去查了 `flyway_schema_history` 的实际内容，发现只有一行 baseline 记录 → 推出「`baseline-version` 之下不逐条记账」→ 确认文档约定的两种部署都不受影响，并把残余风险精确限定在「`baseline ≤ 8` 的环境」。这让一个看起来必然有风险的 L4 变更，变成了有明确边界的低风险变更。
3. **对不可静态检测项做到了「撤除 + 登记 + 实测兜底」三件套**。「探针方向写反」门禁抓不到，我没有改测试去迁就，也没有硬说它通过，而是撤掉该用例、登记为不可静态检测，并**真的把方向反写后跑两次**，用 `ERROR 1060` 证明「跑两次」这一手段确实能覆盖该盲区。
4. **发现并公开了自己新增断言的空转**。`STRUCT_DDL_RE` 因尾反引号必需而扫不到无引号标识符，导致断言「通过但什么都没做」——这是最坏的一类缺陷（假安全感），且是我自己刚写的。

## 问题

1. **同一个错误在同一会话里犯了第三次**：用正则扫 SQL 时**只取每条语句的第一个匹配**，导致把 13 个子句数成 6 个。前两次分别是敏感词词对扫描、`selectByStatus` 守卫扫描。**同一个思维捷径在同类任务上重复失手三次**，说明我并没有从第一次失败里提炼出可执行的防线。
2. **台账失准被我当成事实继承了将近一整轮**。我最初直接引用台账的「6 份」去做风险评估，直到动笔写方案要数具体语句时才发现对不上。台账是**人维护的二手记录**，我在前两轮已经因为「照抄台账措辞」被自己的措辞带偏过一次（#21 的严重性），这次又是同类。
3. **新增静态断言后，我先跑基线自检确认「通过」，就当它工作了**。基线自检只能证明「当前仓库不触发它」，**不能证明它扫得到目标**。真正暴露问题的是后面的反向变异。如果我在写完断言后立刻做一次「故意造一条无守卫 DDL 看它报不报」，能早两轮发现空转。
4. **判定窗口用了「向上 1200 字符」这种经验值**，没意识到相邻语句的守卫会替当前语句背书。这与 AGENTS §2.1 第 8 条是同一类（子串断言只在唯一形态下成立），但那条纪律写在「验证的十一条硬纪律」里，我做**门禁**时没有回头对照。

## 原因

1. 「正则扫一遍文件、统计匹配数」这个做法看起来足够，且**容易在结果「看起来合理」时停下**（数出 6 个不突兀）。真正需要的是**先确定「应有多少个」，再看实扫到多少**——而「应有多少」必须靠**按语句切分后逐条清点**得出，不能靠正则。
2. 台账与变更日志在我这里承担了「事实缓存」的职能，而缓存没有失效机制。上一轮我刚因为台账措辞下错判断（#21），却没把「台账是二手记录、必须重算」变成固定动作。
3. **基线自检给了虚假的安全感**。它是我自己设计的验证步骤，跑通了就成了「验证完毕」的信号，反而抑制了「这条断言真的在做事吗」这个更根本的问题。
4. 门禁开发与「被门禁检查的对象」是两类任务，我用后者的纪律标准要求了前者，但纪律条目本身挂在「验证」章节，读门禁代码时不会去对照。

## 改进方案

| # | 改进 | 落点 |
|---|---|---|
| 1 | **扫 SQL 前先按语句切分并逐条清点，得到「应有多少」；再用正则/门禁交叉验证实扫到多少。两者不等即停** | 本次已落地。拟补入 AGENTS §2.1 作为第 13 条纪律（与第 8 条「子串断言」同族，但更前置：先确定基数） |
| 2 | **台账/变更日志是二手记录，涉及数量与范围的任何断言必须当场重算**，不得引用其措辞作为前提 | 本次已在台账 #10 行内写明「先订正台账自身失准」及两处具体错账 |
| 3 | **新增静态断言后，必须先造一条「它本该抓住」的反例并确认它报出来**，再谈基线自检。基线自检是**必要不充分**条件 | 本次由变异检验的第 3 条（002 无引号 `ADD INDEX`）实际完成。建议补入 AGENTS §2.1 第 1 条的清单要求 |
| 4 | 写门禁判定逻辑时，**判定边界必须显式定义**（按语句 / 按行 / 按括号配平），禁用「向上 N 字符」这类经验窗口 | 本次已改为按语句边界，理由写进门禁注释 |
| 5 | 不可静态检测项统一登记为「**盲区 + 兜底手段 + 兜底手段的实测证据**」三字段，缺一不算登记完成 | 本次 QA 已按此格式记录 2 项 |
