# Retro — 遗留 #19 @ 提及 ID 形态收紧

- Change: `openspec/archive/2026-10-12-at-mention-id-shape`
- 日期: 2026-10-12

## 做得好的

1. **先证伪台账再动手**。台账把该条写成「跨端契约 + 会导致红点提醒」，两条都成了决策前提。
   按 §2.1 第 12 条逐一验证后发现**两条均不成立**：服务端只读 `atAll` 布尔标记不解析正文、
   `atUserIds` 全仓**只写不读**。严重性因此从「中」下调为「低」，
   **避免了为一个不存在的危害去改动跨端契约**。同时实测出 `@Ubuntu` 提取为 `Ubuntu` 而非台账记的
   `buntu`（`.match()` 带捕获组返回完整匹配）——台账的示例值本身就是错的。
2. **追到了真根因**。用户可见症状在正则，但正则不敢改是因为**字符集无上界**：
   靓号路径零格式校验。配套修而不是单点修，避免了「正则收紧 → 字母靓号用户彻底无法被 @」这个
   比原缺陷更严重的后果。
3. **活库取证替代推断**。动手前先查活库：`user_id` 4/4 为 `U`+11 数字、靓号池 **0 行**、
   `at_user_ids` 无数据 → 存量零影响、无需迁移，从论证升级为实证。
4. **`Urobot` 这个坑是查常量的意外收获**。差点直接写成 `@(U\d+)`，
   是 `Constants.ROBOT_UID = "U"+"robot"` 的发现拦住了——它是有头像文件、有会话的真实系统账号。
   该形态当前丢掉也无后果（字段只写不读），但那属于**靠死字段侥幸正确**，
   将来有人基于 `atUserIds` 实现提醒时会静默失效。

## 问题

1. **我自己写了一条与设计决策冲突的用例**。把 `a@U123.com` 放进「不得误命中」清单，
   而 ADR-002 恰恰决定不加左边界（即接受该假阳性）。红阶段本该抓实现，却抓出了我自己。
2. **门禁 B5 在改动后失效了一轮**。它断言的是旧正则字面量 `/@\(U\[A-Za-z0-9\]/g` 出现一次，
   收紧后必然不再命中 —— 说明「唯一性守卫」与「形态」两类断言被混在了一条里。
3. **编辑过程中一度误删了测试体**（`chat-message-voice-mount.spec.js` 的一次 edit 替换掉了整个
   `it(...)` 块），靠回读发现。编辑工具的字符串替换不会校验结构完整性。

## 原因

1. 写用例时**没有回看 ADR-002 的取舍**，把「直觉上该被拦下的」当成了需求。
   即便是自己刚写的决策文档，也没在写测试时对照。
2. B5 最初只为一个目的写（防止正则分叉成两份），后来顺手把形态也塞进去，
   两者变更节奏不同却共用一条断言。
3. `edit` 只做字符串替换，对「替换范围是否恰好等于意图」无校验。

## 改进方案

1. **取舍类决策必须配一条「显式断言残留」的用例**。凡是「我决定接受某个缺陷」的取舍，
   都要有一条用例把该缺陷**当前行为锁死**并注明为什么接受，
   防止后人把它当 bug 顺手修掉而引入更严重的回归。本次已落地：
   `a@U123.com` 用例 + 门禁 C5 + spec 的「有意接受的残留」段落，三处同步。
2. **唯一性守卫与形态断言拆开**。B5 只管「恰好一处」，形态交给 C 组；
   并在 B5 的失败信息里**写明期望形态**，让改形态的人立刻知道还有哪里需要同步。
   （本次已改为失败信息携带形态提示。）
3. **大段 edit 后立即回读**。本次已按 §2.1 第 11 条执行，确实拦下了一次误删。
   建议把「替换的 oldString 超过 ~10 行」视为强制回读阈值。
