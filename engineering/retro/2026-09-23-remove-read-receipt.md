# Retro — 删除已读回执功能

- 日期: 2026-09-23
- 效率等级: L4

## 做得好

- L4 关卡严格执行：四件套先落盘、人工勾选批准后才动第一行代码；范围（含 DROP 表）由人工拍板而非自行推断。
- 按符号定位删除、逐任务 DoD 即时回填 tasks.md，双仓 grep「残留=0 + 保留项≥N」双向核对，避免只证删了、不证没误删。
- 冒烟证据逐阶段落盘（404 curl、收帧/落库 SQL 摘录、踪迹累计扫描、回滚对账），结论与证据一一对应；基线对账用「会话行数」口径复核后与旧基线逐项吻合。

## 问题

- electron-vite watcher 对主进程改动未触发 electron 重启，运行中实例继续跑旧主进程代码，直到手动重启才加载新代码。
- 渲染层文件改动触发 dev 实例整页 reload，用户 B 实例被带回登录页（主进程/WS 无损，但 UI 登录态丢失）。
- 冒烟图片消息第一次上传 600：漏了 `messageId` 必传参数；预览回滚第一次用「最新消息内容」subquery 取错值；`node -e` 内联 SQL 引号被 PS5.1 吞掉报语法错——均为已知环境坑复踩。
- A' 实例冒烟后进程自行结束（日志无错误，疑似窗口被手动关闭），UI 目验窗口失去载体。
- 基线记录口径歧义：旧基线「U2995=11」实为会话行数，与全表总行数（16）对不上，一度误判为残留。

## 原因

- dev 模式下「共享源码的多实例 + HMR/reload」与「主进程不自动重启」并存，改动即影响所有实例且新代码生效路径不直观。
- 复用既往临时脚本/命令时未先核对参数清单（uploadFile 的 messageId）与语义（preview 归属），且 PowerShell 5.1 作为宿主对内联脚本引号不友好。
- 基线快照记录时只写了数字，未标注统计口径（会话范围 vs 全表），复核者只能靠猜。

## 改进方案

- 冒烟前置检查单：确认「运行实例主进程 = 当前工作区代码」（比对 pid/StartTime 或重启策略），写入 tasks 冒烟任务 DoD。
- 基线快照统一模板化：每项计数必须附口径（表/会话/用户）与关键锚点值（预览内容、时间、no_read），复用 `engineering/` 冒烟记录格式。
- 凡涉数据库/复杂内联的自动化操作一律先写临时脚本文件再执行，不在 PS5.1 命令行内联引号嵌套的 SQL/JS。
- UI 类验收在任务拆分时即标注前置条件（需登录实例、需截图），避免收尾时才发现无载体。
