# Retro — 名单解析契约与实现对齐

- 日期: 2026-10-05
- 效率等级: **L3**

## 做得好

- **把「活库核查」写进 tasks 而非事后补**：`T0.2` 从一开始就是显式任务项，
  因此它未执行时能立刻定位到「哪一项欠着」，而不是悄悄消失。
- **D1 与 D2 被识别为同根**：初版我以为是两个独立 bug（空串没忽略 / 空白没 trim），
  读代码后发现是**同一个原因**——规范化顺序反了。这让修复从「加两个判断」变成
  「调换顺序 + 补第二次 trim」，改动更小也更容易说清。
- **变异用例专门覆盖了注释里的论断**：「两次 trim 不可省」这句话如果没人验证，
  它就只是我的断言。补了「去掉第二次 trim」这条变异后，那句话才成立。
- **未执行项与已执行项在 DoD 里分开列**：T0.2 明确写「未执行，未按无影响计」，
  而不是打勾蒙混。

## 问题

- **转义层级又错一层**（本会话第五次）：测试里写 `"[\"\\t\"]"` 想表示「引号内含制表符」，
  但 Java 转义 `\t` 到达 `parse` 时是**字面反斜杠 + t**，不是制表符。
  结果：`parse` 剥引号后剩两字符（非空白）→ 用例持续红，而我一度以为是实现的问题。
  真实成本：多跑了两轮 mvn 才定位。
- **探针与测试同时红时，先怀疑探针**：我先跑探针确认实现行为正确，
  才定位到是测试字面量写错。若顺序反过来，会去「修」一个正确的实现。
- **T0.2 从设计上就注定不可达**：沙箱没有 MySQL，我仍把它写成常规任务项，
  直到执行时才发现无法完成。**明知不可达的 DoD 项，应该在计划阶段就标注并替换为替代证据**
  （本次的替代是 ADR-002 的论证，但那是执行阶段才想出来的）。

## 原因

- **多层转义在「写测试」时不可见，只在「字符串到达被测函数」时显形**：
  源码里 `"\t"` 看起来确实是「反斜杠+t」—— 写的时候我就是这个意思。
  需要的是「到达被测函数时的字面值」，而那只有实跑才知道。
  → 已就地注释说明，但更稳的做法是**在测试里统一用拼接表达控制字符**
  （`""" + "\t" + """`），避免任何多重转义。
- **DoD 可达性未在计划阶段校验**：与前一个 Change（@ 提及的 UI 截图）**同一个根因**，
  已在那个 retro 里记过。两次同类问题说明**这条需要在流程里固化**，
  而不只是写进 retro。

## 改进方案

- **测试中出现控制字符/特殊字符时，一律用字符串拼接**表达，并在旁注说明原因。
  本仓已有先例：`utils/callFrameCore.mjs` 的帧号、`verify_ws_frame_parity.mjs` 的帧表。
- **写 `tasks.md` 时对每个 DoD 项标注「沙箱内可产出 / 需外部条件」**：
  不可达项当场替换为替代证据形式（如本例的 ADR-002 论证），
  不要留到执行阶段才发现。
  **这条已连续两个 Change 踩到，建议作为 L3/L4 计划阶段的固定检查项。**
- **探针优先于断言**：当探针与测试结论冲突时，先确认探针本身的输入
  与测试的输入是否是**同一个字面值**（本例差异就在转义）。
