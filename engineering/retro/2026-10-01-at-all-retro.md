# Retro — @所有人

- 关联 Change: openspec/changes/2026-10-01-at-all/
- 日期: 2026-10-01
- 等级: L3

## 做得好

1. **复用既有契约而非新增接口**。@所有人 标记走 `extraData` JSON 的 `atAll` 字段，
   与既有引用回复（`quoteId`）、@成员（`atUserIds`）共用同一条透传链路，
   服务端、WS 协议、本地表结构零改动，回滚成本极低。
2. **顺带修掉一处既有缺陷**。原 `buildExtraData()` 是「引用」与「@成员」二选一的
   early-return：引用消息里 @ 某人会被静默丢弃。本次改为合并组装，三者可共存。
3. **兼容性双判**。`isAtAll` 同时认 `extraData.atAll` 与正文含「@所有人」，
   即使 extraData 因故丢失（如本地 SQLite 未持久化该列），样式仍正确。
4. **权限双重保险**。模板层 `v-if="canAtAll"` 不渲染选项，逻辑层 `selectAtAll()`
   再校验一次——纯前端隐藏并非安全边界，此处至少保证 UI 与逻辑口径一致，
   真正的服务端鉴权留待后续（见「问题」第 2 条）。

## 问题

1. **自查阶段漏了一个必崩缺陷**。模板加了 `ref="inputRef"` 却忘记在脚本声明
   `const inputRef = ref()`，ESLint `no-undef` 报出后才修复。若只跑构建不看 lint，
   该问题会一路带到运行时——用户点 @ 即整页白屏。
2. **权限只在客户端**。普通成员只要手工构造请求，在 `extraData` 里塞 `atAll:true`
   即可让消息显示 @所有人 样式。当前无服务端校验。
3. **验证证据不完整**。受环境限制（无后端、无双账号、无可交互运行环境），
   端到端联调与页面截图均未执行，QA 结论只能是「需人工决策」而非「通过」。
4. **tasks 与实际落点不符**。计划让 Chat.vue「处理 @所有人 消息发送」，
   但实施后发现发送链路与 @成员提及完全同构，新增分支只会是死代码，
   实际未改动 Chat.vue。

## 原因

1. Vue `<script setup>` 中模板 ref 与脚本变量是两处独立声明，纯靠人眼容易漏；
   组件内既有 `uploadRef` / `searchAddRef` / `drawerRef` 等同类写法分散在各文件，
   无统一约定，靠的是「写的时候记得」而非机制保障。
2. 本期定位为纯前端交互增强（proposal 明确「无新增接口、无表结构变更」），
   权限校验被归入「前端隐藏即可」，未评估绕过成本。
3. 验收环境未随任务就绪，且 L3 的 DoD 对 UI 改动要求截图证据，任务排期时未预留。
4. 四件套在动手前撰写，此时对既有代码的 @ 提及实现尚未通读，
   design.md 的模块分工表是基于推测而非事实。

## 改进方案

| # | 改进 | 落点 | 优先级 |
|---|------|------|--------|
| 1 | 引入 lint 作为提交前硬门禁（`npm run lint` 且 error 数为 0 才允许提交），把 `no-undef` 这类必崩缺陷挡在提交前 | `package.json` scripts + 提交钩子 | 高 |
| 2 | @所有人 权限下沉到服务端：`saveMessage` 校验发送者 role ∈ {0,1}，否则拒绝或降级为普通消息 | 后续单独 Change（L4，涉及权限语义） | 高 |
| 3 | 前端 L3 任务排期时同步确认验收环境（后端 + 双账号 + 可交互运行），把截图与端到端联调写进 tasks.md 验收标准 | 任务排期流程 | 中 |
| 4 | design.md 的模块分工表须在通读相关既有代码后再落笔，避免基于推测的分工造成 tasks 与实现脱节 | 四件套撰写顺序 | 中 |
| 5 | 沉淀组件编写约定：模板 ref 必须在同文件 `<script setup>` 内声明同名变量，纳入前端 AGENTS.md | `easychat-front/AGENTS.md` | 中 |
