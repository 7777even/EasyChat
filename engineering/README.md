# engineering/ — 研发过程记录

本目录存放**短期、一次性**的研发过程记录，与长期知识库 `docs/` 严格分离。文件命名统一 `YYYY-MM-DD-<kebab-slug>.md`。

## 四个子目录

| 目录     | 记什么                                                                     | 何时写                   |
| -------- | -------------------------------------------------------------------------- | ------------------------ |
| `plans/` | 推进计划、里程碑台账、阶段性排期                                           | 排期确定或调整时         |
| `qa/`    | 验证过程与结果：范围、验收口径、实际命令与用例数、未运行项、结论、证据附件 | L3 / L4 交付前必写       |
| `retro/` | 复盘：做得好、问题、原因、改进方案                                         | L3 / L4 收尾、故障复盘时 |
| `ship/`  | 发布检查与回滚方案（上线前逐项确认）                                       | 每次进共享环境前         |

L0 / L1 / L2 改动默认不写这些记录。

## 四条纪律

1. **不写第二套任务**：目录里只记状态和证据，实施任务永远以 `openspec/changes/<name>/tasks.md` 为准，不得在本目录另立任务清单。
2. **报告实际执行的命令**：写清跑了什么、通过多少、哪些没跑。禁止把未执行写成通过。
3. **证据附得上**：接口类改动附 curl / 冒烟终端输出快照；UI 改动附页面截图。
4. **临时产物不放这里**：构建日志、`target/` 产物、diff 快照等一次性文件用完即删，不入库。

## 模板

- QA：从 `templates/_qa_template.md` 复制填充。
- Retro：从 `templates/_retro_template.md` 复制填充。
- 发布检查：从 `templates/_ship_template.md` 复制填充。
