# Design — 稍后处理

- 关联 Proposal: 2026-10-01-later-handle/proposal.md
- 创建日期: 2026-10-01

## 1. 架构设计

```
用户右键消息 → 选择「稍后处理」→ 保存到本地 SQLite → 1小时后系统通知提醒 → 点击通知跳转会话
```

### 前端改动

| 模块 | 改动 | 职责边界 |
|------|------|----------|
| ChatMessage.vue | 右键菜单新增「稍后处理」选项 | 用户交互入口 |
| Tables.js | 新增 later_handle 表定义 | 本地数据库表结构 |
| LaterHandleModel.js | 新增 Model 层 | 本地数据访问 |
| ipc.js | 新增稍后处理 IPC 通道 | 主进程通信 |
| index.js | 新增稍后处理提醒逻辑 | 系统通知 |

## 2. 接口设计

无新增接口。

## 3. 数据模型

本地 SQLite 新增表 `later_handle`：
| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | INTEGER | 自增ID |
| `message_id` | TEXT | 消息ID |
| `session_id` | TEXT | 会话ID |
| `contact_id` | TEXT | 联系人ID |
| `contact_name` | TEXT | 联系人名称 |
| `content` | TEXT | 消息内容摘要 |
| `create_time` | INTEGER | 标记时间 |
| `remind_time` | INTEGER | 提醒时间 |

## 4. 安全设计

- 本地存储，不上传服务器
- 同时最多 10 条稍后处理消息
- 提醒时间固定 1 小时

## 5. ADR

### ADR-001: 稍后处理存储方式

- 状态: 已接受
- 上下文: 稍后处理消息如何存储？
- 决策: 本地 SQLite 存储
- 后果: 实现简单，但无法跨设备同步

## 6. 风险与缓解

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|----------|
| 本地数据丢失 | 低 | 中 | 用户可手动清除稍后处理 |
| 提醒通知过多 | 中 | 低 | 限制最多 10 条 |

## 7. 依赖与前提

- 无前置依赖
