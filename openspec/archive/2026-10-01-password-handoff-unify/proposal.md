# Proposal — 统一密码传递口径，修复登录必然失败

- 创建日期: 2026-10-01
- 效率等级: L4（认证鉴权语义）

## Why

2026-09-30 的 `password-bcrypt` 变更把服务端密码存储升级为 BCrypt，但**前端登录仍沿用 MD5 客户端哈希**，导致四条密码链路口径分裂：

| 链路 | 客户端发送 | 服务端行为 | 结果 |
|---|---|---|---|
| 注册 | 明文 | `bcrypt(明文)` 入库 | 入库成功 |
| **登录** | **`md5(明文)`** | `matches(md5(明文), bcrypt(明文))` | **必然失败** |
| **登录（存量 MD5 账号）** | **`md5(明文)`** | `md5(md5(明文))` vs 存量 `md5(明文)` | **必然失败** |
| 修改密码 | 明文 | 明文校验通过 → 重写为 BCrypt | 成功（但改完仍登不上） |
| 找回密码 | 明文 | `bcrypt(明文)` 入库 | 成功（但仍登不上） |

即：**当前桌面端任何账号都无法通过登录页进入系统**，且该缺陷未被任何自动化验证拦住——`UserInfoServiceImplTest.login_success` 只构造了 MD5 老账号，`scripts/smoke/*` 的登录证据全部早于 2026-09-30，QA 报告已如实把「手动验证登录/注册/改密」列为未运行项。

## What Changes

统一口径为「**客户端发明文，服务端 BCrypt 承担存储与校验**」，删掉前端这一层无意义的客户端哈希。

- 后端: **零改动**。`UserInfoServiceImpl` 已具备 BCrypt 验证 + MD5 双验证 + 登录时自动升级，无需调整任何业务规则。
- 前端: `views/Login.vue` 登录分支移除 `md5()` 包装与 `js-md5` import（`js-md5` 全仓仅此一处使用）。
- 数据库: 无变更（`user_info.password` 已为 60 字符）。
- 连带修正: `scripts/smoke/*.py` 共 7 个脚本 + `probe_admin.py` 登录处发送 MD5，需改为明文，否则改造后冒烟脚本全量失败。
- 不动 `package.json`：`js-md5` 依赖项删除属前端依赖变更（L3），不在本 L4 修复范围内，另开变更处理。

## Capabilities

- C1: 四条密码链路（注册 / 登录 / 修改密码 / 找回密码）传递口径统一为明文，服务端统一以 BCrypt 存储与校验，新注册账号可注册后立即登录。
- C2: 存量 MD5 账号在统一口径下仍可登录，并在登录成功时自动升级为 BCrypt（用户无感、无需批量迁移）。
- C3: BCrypt 登录 / 注册 / 改密路径具备回归单测；登录失败原因可从服务端口径与客户端口径两侧各自定位。
- C4（活体验证后追加）: 存量库结构与基线对齐——`user_info.password` 列宽 32→60，并补齐 `emoji` / `favorite` / `user_status` / `operation_log` 四张缺失表，使 2026-09-30 之后的 DDL 变更具备可执行的迁移路径。

## Impact

- 对外接口: **DTO 签名不变**（`password` 仍是字符串字段），但**取值口径变化**——调用方必须发送明文。仓库内唯一调用方为 Electron 客户端与 `scripts/smoke`，均在同一版本内可控。
- 存量数据: **原判断「无迁移」已被活体验证推翻**。实测存量库 `user_info.password` 为 `varchar(32)`，BCrypt 哈希 60 字符写入被 MySQL 截断拒绝（`Data too long for column 'password'`），导致登录成功前的自动升级抛异常、接口返回 HTTP 500 / `CODE_1002`。同时存量库缺 4 张表（详见 C4）。本变更因此**必须包含一份迁移脚本**（`easychat-migration-010-password-and-im-tables.sql`），这正是「DDL 只改基线、不写迁移」这一流程缺口在鉴权域的首次暴露。
- 性能 / 安全: BCrypt 校验开销不变。**传输层仍无 TLS**，客户端 MD5 并不提供传输机密性（本就是伪安全），移除后不降低实际安全性；真正解决需 HTTPS，属独立变更。
- 回退方案: 代码部分 `git revert` 单文件 `Login.vue` + 冒烟脚本改动即可完全回退；DDL 部分列宽放宽与建表均为向后兼容变更，回退只需保留新增表、不做 DROP。
