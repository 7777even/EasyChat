# Proposal — 新消息提醒：任务栏图标闪烁 + 提醒开关（对标微信）

- 创建日期: 2026-09-24
- 效率等级: L3
- 需求修订: 2026-09-24 人工当场指令——原「系统横幅 + 声音 + 点击跳转会话」方案**撤销**，改为对齐微信的任务栏图标闪烁。
- 实现修订 2: 2026-09-24 人工验收反馈——最小化场景单次 `flashFrame` 仅静态红底、无闪动，改为主动交替闪烁循环（非最小化保持静态高亮）。

## Why

对标微信：窗口失焦时收到新消息，微信以**任务栏图标闪烁**提醒。现状 EasyChat 对所有 WS 帧无条件 `flashFrame`（含 ACK/SYNC/系统帧，属误闪），且无开关可关；系统横幅方案经人工否决（微信不做右下角横幅）。本变更把闪烁收敛为「仅新消息类帧触发、可开关」的正式提醒能力。

## What Changes

- 后端: **零改动**——不新增/修改端点、不动 WS 协议与包络、无错误码变动。
- 前端:
  - 主进程: 新增 `src/main/notification.js`（闪烁抑制规则 + `flashFrame` 调用）；`wsClient.js` **移除** `onmessage` 顶部对全部帧的无条件闪烁，改为白名单消息（2/5/4）收帧后调用 `flashOnNewMessage`；`ipc.js` 集中注册 `updateSysSetting` 通道（写入开关，复用既有 `UserSetting.updateSysSetting`）+ 登录初始化开关缓存。
  - 渲染进程: `UserInfo.vue`（账号设置页）新增「新消息通知」el-switch（控制闪烁，读写既有 `sysSetting` JSON）；`Chat.vue` **零改动**（原计划的 `notificationClicked` 监听随需求修订移除）。
  - preload: **零改动**——闪烁为主进程对窗口的系统调用，不新增 `contextBridge` 暴露面（规避 §5 L4 门禁）。
- 数据库: 无表结构 / 字段变更。开关存于既有 `user_setting.sysSetting` JSON 新增键 `notifySwitch`（缺失视为开启），不动 `Tables.js`，无迁移。

## Capabilities

- C1: 新消息图标闪烁——主窗口未聚焦时收到新消息（单聊/群聊文本 2、媒体 5、好友申请 4），触发任务栏图标闪烁直至窗口获得焦点：**最小化场景为主动交替闪动动画**（600ms 周期亮/灭循环，微信式图标闪烁——单次 `flashFrame` 在最小化窗口上仅渲染静态高亮、不产生闪动）；**非最小化失焦场景为系统静态红底高亮**（人工验收确认可接受）；聚焦时不闪；ACK/SYNC/心跳/撤回/系统帧不闪（收敛既有全帧误闪）；不误报自身消息回声与重连补推的过期消息。**无横幅、无声音、无点击跳转**——点击任务栏按钮由系统原生激活窗口（微信同款交互）。
- C2: 提醒开关——设置页可关闭/开启新消息闪烁，默认开启，持久化到本地 `sysSetting` JSON，重启后生效保持；关闭后不闪，消息收发与未读数不受影响。

## Impact

- 对外接口: 无。后端契约调用方无需同步。
- 存量数据: 无影响，无迁移（`notifySwitch` 缺省即旧值语义）。
- 性能 / 安全: 每条新消息多一次 `flashFrame` 系统调用（可忽略）；**无通知正文外显**（原横幅方案的锁屏隐私风险随撤销一并消除）；不改 WS 链路/心跳/包络（§5 L4 项逐一规避）。
- 行为变更（对内）: 既有「任意 WS 帧失焦即闪」收敛为「白名单新消息才闪」——撤回/群管理/上传完成等系统帧不再触发闪烁（微信对齐）。
- 回退方案: revert 单个 commit 即回到全帧闪烁状态，`sysSetting` 中残留 `notifySwitch` 键无副作用。
