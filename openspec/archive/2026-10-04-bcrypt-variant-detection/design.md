# Design — BCrypt 哈希变体识别与 `matches()` 对齐

- 关联 Proposal: `openspec/changes/2026-10-04-bcrypt-variant-detection/proposal.md`
- 创建日期: 2026-10-04

## 1. 缺陷的准确形态

`isBCrypt()` 是**格式判定**，`matches()` 是**校验**。二者本该满足：

> **不变式 I**：`isBCrypt(p) == false` ⟹ `matches(anything, p)` 不可能成功。

当前实现违反该不变式：`matches` 认 `$2b$`/`$2y$`，`isBCrypt` 不认。

注意不变式的**方向**——`isBCrypt` 判 `true` 而 `matches` 判 `false` **是安全的**
（登录返回密码错误，不改数据）；反向才危险。所以修复方向只能是**放宽** `isBCrypt`。

## 2. 后果逐条（`UserInfoServiceImpl` 四处调用）

设库中密码为 `$2b$` 开头的合法 BCrypt 哈希：

| 位置 | 当前行为 | 后果 |
|------|----------|------|
| `login:266` | `isBCrypt`=false → 走 MD5 分支 `password.equals(MD5(password))` | 恒 false → **登录失败**（尽管 `matches` 本可通过） |
| `login:288` | 登录成功后判定「非 BCrypt」→ `encode(password)` 再加密一次 | **双重加密**，密码永久错乱，且此后无人能登录 |
| `updatePassword:403` | 同 266 | **改密失败**（旧密码校验过不去） |
| `updatePassword:413` | 「新密码不能与原密码相同」判定走 MD5 基线 | 判定结果错误 |

`login:288` 是**唯一造成不可逆数据损坏**的一处：它把已加密的哈希当明文再加密一次。

## 3. 实证：Spring 5.6.0 到底接受哪些前缀

探针枚举全部 minor 字符，跑通后已删除（`git status` 干净）：

```
基准哈希 = $2a$10$
$2a$ -> true      $2b$ -> true      $2y$ -> true
$2c$~$2z$、$20$~$29$  -> false
$2$（无 minor）  -> false
$2A$（大写）     -> false
$1$（非 bcrypt） -> false
$2a$ 但长度不足   -> false

Spring 接受的 minor 集合 = [aby]
```

**`$2x$` 被 Spring 5.6.0 拒绝**，尽管 BCrypt 规范/OpenBSD 实现列有 `2x`。
这说明「照抄某个版本的接受集合」是错的做法——它会随 Spring 版本漂移。

## 4. 决策

### ADR-001：`isBCrypt` 放宽为 BCrypt **全部已知变体**，而非照抄 Spring 当前接受集

- **决策**：接受 `$2a$` / `$2b$` / `$2x$` / `$2y$`（BCrypt modular crypt format 的完整已知变体集）
- **理由**：
  - 不变式 I 要求 `isBCrypt` 是「Spring 能校验的哈希」的**超集**。
    放行 `$2x$` 而 Spring 5.6.0 校验不了 → 登录返回密码错误 → **安全**（不变式方向正确）。
    反之漏放某个未来 Spring 开始支持的变体 → 双重加密 → **不可逆损坏**。
  - 因此**宁可放过、不可错过**。这是安全方向上的单向选择。
- **备选与否决理由**：
  - ❌ 照抄 `[aby]`：Spring 一升级就可能新增变体，届时本实现立刻退化为原缺陷，且**无声**
  - ❌ 用 `startsWith("$2")`：会把 `$2$`（无 minor，Spring 拒绝）、`$20$`~`$29$` 也放进来，
    判定过宽，掩盖真正的非 BCrypt 数据
  - ❌ 复用 `matches()` 探测：Spring 的 `matches` 内部 `catch (IllegalArgumentException)`
    并返回 `false`，**无法区分「密码错」与「不是 bcrypt 格式」**，此路不通（已实测排除）

### ADR-002：测试断言的口径由 **Spring 行为实测推导**，不硬编码

- **决策**：测试内先探测「当前 Spring 接受哪些前缀」，再断言
  「凡 Spring 接受者，`isBCrypt` 必须返回 true」
- **理由**：硬编码 `[aby]` 的测试会在 Spring 升级后**假绿**——
  测试与实现同时基于过时的知识而互相印证，正是 §2.1 纪律 1「门禁须先有判别力」的典型反例。
  推导式断言使测试随依赖自动校准，任何一方漂移立即转红。
- **同时保留硬编码断言**：显式要求 `$2a$`/`$2b$`/`$2y$` 必须在放行集内，
  使「实现意外收窄」也能被发现（推导式断言只保证不漏，不能发现多拒）。

### ADR-003：不做数据迁移，不动存量

- **决策**：仅改判定方法，不写任何迁移脚本
- **理由**：现网哈希全为 `$2a$`，新旧实现判定**完全相同**。
  写迁移等于为不存在的差异付出风险面。§6.4-2 要求「改基线必须同批产出迁移」，
  本变更**不改基线**，故不适用。

### ADR-004：同时要求定长 60 —— **红阶段追加**，人工确认后纳入

**发现路径**：TDD 红阶段（先写测试、跑红、再改实现）在组 B 抓到**第三个反例**：
首版实现 `startsWith("$2a$")` 会把 `"$2a$"`、`"$2a$10$tooshort"` 这类
**根本不构成 BCrypt 哈希的截断串**判为 `true`。即缺陷是**双向**的，不只「判严」。

**这修正了 proposal 阶段的错误判断**。当时（未经实证）我认定「长度校验不增安全性、
只增加出错面」，理由是「`matches` 会兜底」。实测证明该理由不成立：

- BCrypt modular-crypt 格式**长度恒为 60**（`$2<minor>$` 7 + cost 2 + `$` 1 + 盐 22 + 哈希 31）。
  这是**格式定义**，不是启发式阈值，故长度校验不构成「额外收紧」，
  而是「正确识别格式」的必要组成部分。
- 变更方向仍然安全：长度不足判 false → 调用方落 MD5 分支 → 校验失败 → **不改数据**。

**已就此单独请求人工确认**（超出 proposal 确认范围，属 L4 不得静默扩大），获批后纳入。

- **备选与否决理由**：
  - ❌ 靠 `matches` 兜底而不校验长度：`matches` 内部 `catch (IllegalArgumentException)`
    并返回 `false`，**无法区分「密码错」与「不是 bcrypt 格式」**，且这正是首版缺陷的成因
  - ❌ 保持首版并删除对应断言：等于削弱测试去迁就实现，且 `isBCrypt` 语义失真
    （它应当回答「这是不是一个 BCrypt 哈希」，而非「这串字符开头像不像」）

---

## 4.5 红阶段的第三重收获：方向反转也能被测出

变异用例「★ 拒绝分支方向反转」（把 `if (password.startsWith(prefix))` 改成
`if (!password.startsWith(prefix))`）**被捕获**。这是台账遗留 **#11** 声称
「静态断言无法验证条件分支方向」的**反例**——该结论对**源码字面量断言**成立，
但对**行为测试**不成立。`docs/system-facts.md` #11 的表述已据此限定适用范围。


## 5. 数据影响

无。`easychat.sql` 不变，无 `easychat-migration-<NNN>` 脚本，`baseline-version` 不 bump。

## 6. 风险

| 风险 | 评估 | 缓解 |
|------|------|------|
| 放宽过头，把非 BCrypt 数据误判为 BCrypt | 低。变体集合是白名单枚举，非前缀通配 | 测试断言 32 位 MD5、`$1$`、`$20$` 等均判 false |
| 未来 Spring 新增变体 | 中 | ADR-002 的推导式断言会自动转红提醒 |
| `isBCrypt` 判 true 但 Spring 校验不了 | **可接受**——登录返回密码错误，不改数据（不变式方向正确） | 已在不变式 I 中显式声明 |

## 7. 验证口径

- `mvn test`：`PasswordEncoderTest` 全绿，且**必须先红**（TDD 红阶段）
- 变异检验：把 `isBCrypt` 改回 `startsWith("$2a$")` → 必须转红；
  把变体集合扩成 `startsWith("$2")` → 必须转红
- `verify_password_handoff.mjs` 仍全绿（该门禁断言客户端不自行哈希，本次不涉及）
- 全量后端测试回归无新增失败
