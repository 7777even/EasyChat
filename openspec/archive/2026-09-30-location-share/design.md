# Design — 位置分享

- 关联 Proposal: 2026-09-30-location-share/proposal.md
- 创建日期: 2026-09-30

## 1. 架构设计

### 后端改动

| 模块 | 改动 | 职责边界 |
|------|------|----------|
| `MessageTypeEnum` | 新增 `LOCATION(25)` | 帧类型枚举 |
| `ChatMessageServiceImpl` | 支持位置消息存储 | 业务规则 |

### 前端改动

| 模块 | 改动 | 职责边界 |
|------|------|----------|
| `MessageSend.vue` | 添加位置选择功能 | UI 交互 |
| `ChatMessageLocation.vue` | 位置消息展示组件 | UI 展示 |

## 2. 接口设计

无新增接口。位置消息复用现有消息发送接口，位置信息存储在 `extra_data` 字段。

## 3. 数据模型

无表结构变更。位置信息存储在 `chat_message.extra_data` 字段：
```json
{
  "location": "北京市朝阳区",
  "latitude": 39.9042,
  "longitude": 116.4074
}
```

## 4. 安全设计

- 鉴权: 复用现有消息发送鉴权
- 数据权限: 复用现有消息权限
- 输入校验: 位置信息格式校验
- SQL 注入防护: 使用 `#{}`

## 5. ADR

### ADR-001: 位置信息存储方式

- 状态: 已接受
- 上下文: 位置信息需要存储在消息中
- 决策: 存储在 `extra_data` 字段，避免新增字段
- 后果: 位置信息以 JSON 格式存储，查询不便

## 6. 风险与缓解

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|----------|
| 位置信息泄露 | 中 | 高 | 用户授权后分享 |
| 位置信息不准确 | 中 | 低 | 使用地图 API 校验 |

## 7. 依赖与前提

- 需要地图 API（如高德地图/百度地图）
- 需要用户授权地理位置权限
